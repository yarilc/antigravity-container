# Security constraints

- Every session drops all capabilities and sets no-new-privileges. Never add capabilities back, add `--privileged` or disable no-new-privileges to fix a tool; record the limitation in `docs/validation.md` instead.
- Sessions have validated, inspected memory, CPU and process budgets (`ANTIGRAVITY_CONTAINER_MEMORY_LIMIT`, `ANTIGRAVITY_CONTAINER_CPU_LIMIT`, `ANTIGRAVITY_CONTAINER_PIDS_LIMIT`; defaults 4g, 2, 512) and an optional `ANTIGRAVITY_CONTAINER_RUN_TIMEOUT`. No value disables a budget. A budget whose cgroup v2 controller the rootless engine does not delegate (`Host.CgroupControllers`) is omitted, announced and bound into the qualification identity; never require host changes to delegate it. Reported controllers count as delegated only with the `systemd` cgroup manager (`Host.CgroupManager`): a rootless `cgroupfs` engine reports controllers but applies no limits, so it delegates none (`delegated()` in `network/agent_budgets.py`, mirrored in `launcher/core.sh`). The process budget alone falls back to a soft and hard process rlimit (`--ulimit nproc`) when the engine kernel (`Host.Kernel`) is Linux 5.14 or later, which counts it per container; the mechanism (`cgroup`, `rlimit` or `none`) is one rule in `network/agent_budgets.py` and `launcher/core.sh`, verified and qualified like a cgroup budget.
- Sessions keep automatic read-only tmpfs provisioning so the engine provides `/dev` and a PTY-capable `devpts`, with an empty read-only `/dev/shm` and `/run/secrets` mask; never reintroduce `--read-only-tmpfs=false`, an explicit `devpts` mount (it gets `ptmxmode=000`) or a writable `/dev/shm`.
- The recipe fetches Debian packages over verified HTTPS only; the host CA reaches the apt and agy download steps only as the `build-ca` secret. It creates `/workspace` in a build step: never declare a `WORKDIR` that no build step creates.
- Sensitive workspace roots (`/`, system directories, `/tmp`, the physical home, `/mnt/<letter>` and the Windows system and profile folders on those drives) are refused unless exactly `ANTIGRAVITY_CONTAINER_ALLOW_UNSAFE_WORKSPACE=1`.
- Image inputs (base digest, `agy` release artifact and SHA-512 per architecture, OpenSpec version) are pinned in `Containerfile` and change only through the README update procedure.
- Run `tests/test_launcher.py`, `tests/test_wrapper.py` and `tests/test_image_pins.py` without credentials; real-engine checks use `bash tests/run-runtime.sh`.

# Network sandbox

- `antigravity-container.sh` is the thin entry script, identical in every wrapper: it sources the shared launcher core `launcher/core.sh` with Antigravity's agent part `agent/launcher.sh` (profile values, the entrypoint as restricted application, executable temporary storage, the fixed `AGY_CLI_DISABLE_AUTO_UPDATE=true`, the `ANTIGRAVITY_YOLO` help and the `--dangerously-skip-permissions` hook). The core owns argument parsing, mounts, state, signals and the session lifecycle; `docs/launcher-contract.md` in `sandbox-container` is its contract. Change launcher behavior there, never here.
- `antigravity-container.ps1` is the thin Windows entry, identical in every wrapper under the wrapper's name: it runs the shared shim `launcher/windows/core.ps1`, which starts the managed installation inside a Podman machine's WSL distribution through `launcher/windows/bootstrap.sh`, and runs sessions and setup in the machine's systemd namespaces through `launcher/windows/enter.sh`. Windows supports every network mode that setup prepared, without Podman delegation; see the README's Windows section. `launcher/windows/` is shared like `launcher/core.sh`.
- An unset or empty `ANTIGRAVITY_CONTAINER_NETWORK` selects `provider`; without a protected installation or the saved provider settings the launch stops with setup guidance. State defaults to the shared `~/.gemini`; `ANTIGRAVITY_CONTAINER_STATE_DIR` selects an isolated home. Every image build and proxy pull needs exact `ANTIGRAVITY_CONTAINER_MAINTENANCE=1`; `--container-build` without `agy` arguments builds and exits. Host Podman delegation is rejected in restricted modes.
- `agent/profile.json` and `agent/policies/default.json` hold every Antigravity-specific value used by the shared network code (identity, images, state layout, the `google-account` and `gemini-api` profiles). Restricted preparation, proxy lifecycle and restricted container arguments come from `network/session.py` (`prepare`, `start`, `agent-args`, `stop`), called by the core.
- `network/`, `setup/`, `launcher/` and the shared tests (`sandbox_profile.py`, `test_alignment.py`, `test_launcher.py`, `fake_podman.py`, `test_setup.py`, `test_agent_profile.py`, `test_network_policy.py`, `test_mux.py`, `test_tls_client_hello.py`, `test_tls_proxy.py`, `test_platform.py`, `test_qualification.py`, `test_guard.py`, `test_session.py`, `test_network_feasibility.py`, `test_toolchains.py` and their fixtures) are copied unchanged from `sandbox-container` at tag `sandbox-ref-28`. Never edit them here, and never add a profile identifier (`antigravity`, `agy`, `gemini`) to them. Fix a defect in `sandbox-container` first, then copy the files again and update `tests/test_reference_copy.py`.
- The shared `setup/toolchains.py` manages the operator toolchain library, mounted read-only at `/toolchains`; the core owns its dispatch, mount and environment, and places the toolchain environment before `AGY_CLI_DISABLE_AUTO_UPDATE=true`.
- There is no D-Bus session or keyring in the container: `agy` keeps account tokens in files in the private state home. Never add a Unix-socket exception to the guard for a bus or another tool.
- New users start with `bash ./antigravity-container.sh --container-setup`; the `account` method declares empty `login_args`, so setup offers sign-in inside the interactive `agy`.
- Run the suites through `bash tests/run-runtime.sh` with `--wrapper`, `--shared`, `--setup`, `--setup-runtime`, `--guard`, `--guard-idle`, `--network-feasibility`, `--network-policy`, `--mux`, `--qualification`, `--network` or no option (unrestricted runtime suite). Automated tests never use real credentials; authenticated Google account and Gemini API-key checks are operator-run.
- Every tracked `*.sh` file, the shared `launcher/core.sh` and launcher fixtures included, passes `bash ../sandbox-container/tools/shellcheck.sh .` (pinned ShellCheck, warning level). Antigravity's agent part `agent/launcher.sh` starts with `# shellcheck shell=bash disable=SC2034,SC2154`, because the core reads its data and defines the state its hooks read.
- Every tracked `*.ps1` file passes `bash ../sandbox-container/tools/powershell.sh .` (pinned PSScriptAnalyzer, warning level), which also runs the shared shim tests `tests/windows/shim_tests.ps1` against a fake `wsl.exe`. The thin entry and the shim stay ASCII and run on Windows PowerShell 5.1 and PowerShell 7; Windows PowerShell 5.1 itself is validated on a Windows host. Scripts keep LF line endings through `.gitattributes`.
